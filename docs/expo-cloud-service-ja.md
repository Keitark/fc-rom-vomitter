# 展示向け匿名クラウドサービス案

> **状態: 設計仕様のみ。** 現在のファームウェアに実装済みなのは、ビルド時に
> 指定した1つのHTTPS URLからの取得です。ここで説明するキュー、端末ネゴシエーション、
> 完了通知は**まだ実装されていません**。

このv2サービスでは、来場者がChatGPTアカウントなしで公開Webページから対応
homebrew ROMを送信できます。サービス側で検査してキューへ登録し、カートリッジが
対応可能なジョブを取得します。HTTPSでダウンロード後、内容を再検査し、安全な
ハードウェア状態でのみ導入して、結果をサーバーへ返します。

最初の公開版は、展示会場で1台のカートリッジをスタッフが監督して使うためのもの
です。無制限なROM配布サービスではありません。送信者が利用権を持つROMだけを
対象にします。

## 役割と信頼境界

| 役割 | 責務 | 禁止事項 |
|---|---|---|
| 匿名の来場者 | ROMを1件送信し、発行された状態確認URLを保持 | カートリッジへの直接アクセス、検査の迂回 |
| 公開Webサービス | 検査、重複排除、キュー、期限切れ、状態表示 | 非公開オブジェクトURLや端末秘密鍵の公開 |
| カートリッジ | 能力通知、互換ジョブ取得、再検査、安全な導入、結果通知 | ブラウザ由来メタデータの信用、危険なバス状態での導入 |
| 運営者 | キュー停止・消去、デモの緊急停止 | 通常の自動運転中に有効なROMを1件ずつ手承認 |

来場者はChatGPTへサインインしませんが、無制限でもありません。サービスはランダムな
HttpOnlyセッションCookieと推測困難な状態確認トークンを発行します。端末APIは別の
端末固有秘密鍵によるHMAC認証を使います。

## 来場者フロー

1. 公開Siteを開き、`.nes`をアップロードする。
2. サーバーがiNESヘッダーと全ペイロードを検査する。
3. 有効で対応可能なイメージだけを自動承認してFIFOキューへ入れる。
4. 推測困難な状態確認URLを返し、ページから進行状況を確認する。
5. `queued`、`claimed`、`downloaded`、`installed`、または終端状態の
   `rejected`、`failed`、`expired`、`duplicate`へ遷移する。

この来場者フローにChatGPTログインは不要です。運営者操作とデプロイ管理は別途認証
します。

### HTTP API案

| methodとpath | 呼出元 | 結果 |
|---|---|---|
| `POST /api/public/jobs` | 来場者browser | uploadを検査し、状態token付き`202`、または範囲を限定した`4xx`拒否を返す |
| `GET /api/public/jobs/{status_token}` | 来場者browser | ROMや端末identityを出さずに公開可能なjob状態を返す |
| `POST /api/device/v2/next` | 認証済みcart | 能力/状態を通知し、`204`またはlease付きmanifest 1件を受け取る |
| `POST /api/device/v2/jobs/{job_id}/result` | 認証済みcart | `installed`、`unchanged`、`deferred`、`failed`を冪等に通知する |

公開用status tokenと内部job IDは別の値にします。状態確認URLが漏れても、ROM取得、
取消、端末操作を認可してはいけません。

## 自動承認ゲート

自動承認とは、任意のデータを無条件で受け入れることではなく、**自動検査に合格した
ものだけを受け入れる**ことです。非公開オブジェクトストレージへ保存する前に、以下を
確認します。

- アップロード上限と完全なiNESヘッダー
- カートリッジの能力プロファイルに合うmapperとPRG/CHR構成
- 明示対応するまでtrainerやNES 2.0固有機能を拒否
- ブラウザ値を信用せず、サーバー側でSHA-256とCRC32を計算
- 待機中・実行中イメージとの重複排除
- セッション/IP単位のクールダウンと有限キュー（初期値20件）
- 完了または期限切れ後の自動削除（初期値1時間）

拒否されたデータには、非公開オブジェクトのダウンロードURLを発行しません。

## 端末ネゴシエーション

展示プロファイルでは2〜3秒ごとにポーリングします。互換性と安全な導入に必要な状態を
毎回通知します。

```json
{
  "device_id": "demo-cart-01",
  "firmware": "2.0.0-dev",
  "protocol": 2,
  "mappers": [0],
  "max_rom_bytes": 41488,
  "active_sha256": "...",
  "console_power": false,
  "console_exposed": false
}
```

互換ジョブがなければ`204 No Content`、あれば短時間だけ有効なmanifestを返します。

```json
{
  "job_id": "01J...",
  "download_url": "https://.../short-lived-object-url",
  "bytes": 40976,
  "sha256": "...",
  "crc32": "d98313b2",
  "ines": { "mapper": 3, "prg_kib": 32, "chr_kib": 8 },
  "expires_at": "2026-09-22T12:34:56Z"
}
```

端末はTLS、バイト数、SHA-256、CRC32、再解析したiNES項目を検査します。その後、既存の
非アクティブFlashスロット、Flash CRC、SRAM読戻し、ファミコン側バス分離の各ゲートを
通します。導入が危険な状態でもダウンロードまでは可能ですが、結果は`deferred`として、
安全になるまで本体側へ公開しません。

処理後は、次のいずれかを冪等に通知します。

- `installed`: 検査を完了して有効化
- `unchanged`: 同じハッシュがすでに有効
- `deferred`: 有効だが安全な本体電源状態を待機中
- `failed`: 端末側で拒否。有限の機械可読エラーコードを添付

リセットや応答消失で二重導入やジョブの永久停止が起きないよう、claimとackにはleaseと
冪等キーを使います。

## Sitesでの保存構成案

ChatGPT Sites版では、サーバー側route、メタデータとキュー状態にD1、ROM本体に非公開
R2を使う想定です。これはデプロイ方式であり、カートリッジプロトコルの必須条件では
ありません。同じAPIを別サービスで実装しても構いません。

| 保存先 | 内容 |
|---|---|
| D1 | セッション、ジョブ、ハッシュ、検査結果、lease、端末状態、ack、期限 |
| R2非公開bucket | ジョブID/ハッシュをキーにした検査済みROM |

公開ブラウザへ永続的なR2認証情報を渡しません。認証済みclaim後のカートリッジにだけ、
短時間のダウンロードURLを渡します。

## 運用保護

- スタッフ専用のpause/resume、次件削除、全件削除、緊急停止
- 最終端末poll、ファーム/能力、有効hash、queue数、最終error、導入保留状態の表示
- 厳格なbody上限、rate limit、origin検査、構造化監査イベント
- account、payment、Wi-Fi、端末秘密鍵をlogへ保存しない
- クラウドや会場ネットワーク障害時もSoftAPブラウザをローカル復旧経路として残す

ChatGPT Sitesは現在、未ログイン来場者への公開、サーバー側コード、HTTP/HTTPS、D1/R2
連携を提供しています。公開前に[公式Sitesドキュメント](https://learn.chatgpt.com/docs/sites)
で最新のベータ制限を再確認してください。

## 実装完了の判定

次を満たすまでv2デモを完成扱いにしません。

1. 不正、過大、未対応、重複、rate limit対象uploadのnegative testがある
2. 端末HMAC、期限、replay、lease回復、冪等ackのtestが通る
3. 本体給電中または危険なbus ownershipでは導入を保留する
4. browser再読込後もqueue状態が残り、最終端末結果まで表示できる
5. 非公開ROMを匿名で列挙・取得できない
6. 実機で運営者pauseと緊急停止を試験する
7. 固定URLのv1モードとSoftAP復旧経路が引き続き使える
